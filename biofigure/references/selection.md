# 跨图型选择：从问题到 Ontology

同一数据可回答不同问题。先选 `scientific_task/message_type`，再选 Pattern 与 primitive，最后叠加领域规则；不按文件扩展名或“组学”关键词套图。

| 要回答的问题 | 候选表达 | 必须保留的信息 |
|---|---|---|
| 组间差多少 | 原始点、效应量与区间、箱线 | 实验单位、方向、不确定性 |
| 分布有何不同 | 点、ECDF、箱线、密度 | n、尾部、带宽或分箱 |
| 随时间怎样变 | 轨迹、分面曲线、动态矩阵 | 真实间隔、配对与重复 |
| 两变量是否相关 | 散点、关联矩阵 | 样本单位、尺度、混杂 |
| 哪些特征重要 | 排序点图、MA、火山、载荷 | 效应、统计来源、筛选依据 |
| 组成怎样变化 | 堆叠比例、点图；有转移数据再考虑流图 | 分母、互斥性、追踪证据 |
| 层级或位置关系 | 树、结构域、轨道、共线性 | 拓扑、坐标、方向 |
| 共享模式如何组织 | 注释矩阵、因子图、模块对照 | 共同顺序、模型含义 |
| 空间/关系网络 | 空间叠图、带证据的网络 | 配准、尺度、边含义 |

Pattern 不是固定模板：它定义 primary/secondary 信息、布局、标注、图例和失效条件；primitive 只定义几何；renderer 只负责执行。先用 `retrieve_patterns.py` 做 eligibility，再做 design-fit 排序。数据结构、信息密度、标注负担、出版宽度和是否分组决定选择。

候选不是白名单。新图型先拆解位置/长度/面积/颜色/连接/注释，再检索作者案例并提炼 visual grammar；复杂本身不是质量。

用户已指定图型且科学上可行时沿用；不合适时说明具体误读风险并给替代方案，不擅自替换需求。不同图型可组合，共享样本、语义与图例规则。

通用精修：按密度安排尺寸，明确视觉重点，精简冗余图例，保留必要轴和标签，检查遮挡/裁切/符号含义，再按最终尺寸看图。方格要求仅在离散矩阵适用。

依据：[图形设计方法](https://pmc.ncbi.nlm.nih.gov/articles/PMC4161295/)。
